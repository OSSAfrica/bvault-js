Encrypt browser storage with a non-extractable CryptoKey.

The encryption key is now generated by the browser with `extractable: false` and persisted in
IndexedDB. Its raw bytes are never exposed to JavaScript, so storage that is copied and replayed in
another browser cannot be decrypted.

**Breaking changes**

- `initializeSecureStorage()` no longer takes a password.
- `encrypt` and `decrypt` are removed from the public API, along with all PBKDF2 key derivation.
- Data written by 0.x cannot be migrated — keys derived from a password or browser fingerprint are
  not recoverable — and is cleared once on first initialization with a warning. Only keys that 0.x
  recorded in its own metadata stores are touched.
- Values are now stored under a `bv1:` prefix so bVault never collides with other libraries' data.

**Added**

- `destroySecureStorage()` deletes the key and every value stored under it.

**Fixed**

- `getItem` no longer deletes the stored value when decryption fails. A transient error, or a key
  evicted by the browser, previously destroyed the user's data.
- Importing the package no longer throws under server-side rendering; `localStorage` was read at
  module load.
- `bufferToBase64` no longer overflows the call stack on payloads larger than ~100KB.

**Withdrawn guidance**

The README no longer recommends deriving the key from a browser fingerprint. Fingerprints are
recomputable by any script in the origin, carry roughly 13 bits of entropy, and drift often enough
that stored data becomes silently undecryptable.
